# koden-mu

株式会社光電製作所の簡易型気象レーダー試作機（プロジェクト番号 #1800077）で取得したIQデータを解析・可視化するPythonスクリプト集です。

## リポジトリ構成

```
src/koden_mu/radar.py        # レーダー処理の共通定数・関数ライブラリ
scripts/process_iq.py        # 単一 .bin を処理して PNG / NPZ を生成
scripts/make_power_gif.py    # ディレクトリ内の .bin を一括処理して GIF を生成
scripts/plot_doppler_sample.py  # NPZ からドップラースペクトルを表示
scripts/plot_time_height.py  # ディレクトリ内の .bin を一括処理して時間・高度図を生成
webapp/                      # 解析結果をブラウザで表示する Web アプリ
```

## スクリプト概要

| スクリプト | 説明 |
|---|---|
| `scripts/process_iq.py` | IQデータ（`.bin`）を読み込み、受信電力マップの描画とNPZファイルへの保存を行う |
| `scripts/make_power_gif.py` | ディレクトリ内の全 `.bin` を一括処理し、電力マップのGIFアニメーションを生成する |
| `scripts/plot_doppler_sample.py` | NPZファイルを読み込み、指定したゲートのドップラースペクトルをプロットする |
| `scripts/plot_time_height.py` | 鉛直観測のディレクトリ内の全 `.bin` を一括処理し、受信電力と平均ドップラー速度の時間・高度図を生成する |

## 環境構築

[uv](https://docs.astral.sh/uv/getting-started/installation/) を使った環境構築を推奨します。

```bash
uv sync
```


## 使い方

### 1. IQデータの処理（`process_iq.py`）

```bash
uv run scripts/process_iq.py <IQデータファイル.bin>
```

実行すると、入力ファイルと同じ名前で以下の2ファイルがカレントディレクトリに生成されます。

| 出力ファイル | 内容 |
|---|---|
| `<入力ファイル名>.png` | PPI形式の受信電力マップ（解像度 300 dpi） |
| `<入力ファイル名>.npz` | 処理済みデータを格納したNumPy圧縮ファイル |

#### NPZファイルの内容

| キー | shape | 説明 |
|---|---|---|
| `power` | `(10, 2048)` | 受信電力 [dBm]。仰角 × レンジの2次元配列 |
| `x` | `(11, 2049)` | 受信電力プロット用のX座標 [km]。`pcolormesh` の境界グリッドとして +1 大きい |
| `y` | `(11, 2049)` | 受信電力プロット用のY座標 [km]。同上 |
| `doppler` | `(10, 2048, 200)` | ドップラー電力スペクトル [dB]。仰角 × レンジ × 速度ビンの3次元配列 |
| `velocity` | `(200,)` | ドップラー速度軸 [m/s]。ナイキスト速度の範囲でfftshift済み |

### 2. 電力マップGIFの生成（`make_power_gif.py`）

```bash
uv run scripts/make_power_gif.py <IQデータディレクトリ> --output <出力.gif>
```

ディレクトリ内の `.bin` ファイルをファイル名順に処理し、各ファイルの PPI 電力マップをフレームとして合成したGIFアニメーションを生成します。

```bash
# 例：2fps、最初のファイルをスキップして生成
uv run scripts/make_power_gif.py D:/IQ_data --output D:/result.gif --fps 2 --skip-first
```

| オプション | デフォルト | 説明 |
|---|---|---|
| `--output` | （必須） | 出力GIFのパス |
| `--fps` | `2.0` | GIFのフレームレート |
| `--azi-num` | `10` | 処理する方位数 |
| `--vmin` | `-130` | カラースケール最小値 [dBm] |
| `--vmax` | `-50` | カラースケール最大値 [dBm] |
| `--skip-first` | オフ | 最初の `_0000.bin` をスキップ |

### 3. ドップラースペクトルの表示（`plot_doppler_sample.py`）

```bash
uv run scripts/plot_doppler_sample.py <NPZファイル.npz>
```

デフォルトでは仰角インデックス `0`、レンジインデックス `0` のドップラースペクトルを表示します。
他のゲートを表示するには `plot_doppler_sample.py` 内の以下の行を編集してください。

```python
ax.plot(velocity, doppler[0, 0, :])
#                         ↑  ↑
#                         |  レンジインデックス
#                         仰角インデックス
```

### 4. 時間・高度図の生成（`plot_time_height.py`）

鉛直上向きで観測したデータについて、降水エコーの時間変化を確認するための図を作成します。

```bash
uv run scripts/plot_time_height.py IQdata_20261030 --output time_height.png --npz time_height.npz
```

出力する PNG は 2 段構成です。

- 上段: 受信電力 [dBm]
  - 静止物の反射を除くため、ドップラー速度 0 付近の成分を除いた電力を表示する
- 下段: 平均ドップラー速度 [m/s]
  - 正の値が下向き（レーダーに近づく向き）で、降水粒子の落下速度に当たる。雨は 4〜8 m/s、雪は 1〜2 m/s 程度になる
  - 信号対雑音比が `--snr-min` 未満のゲートは灰色で表示する

1,000 ファイル（約 16 GB）の処理に約 2 分かかります。

| オプション | デフォルト | 説明 |
|---|---|---|
| `--output` | （必須） | 出力PNGのパス |
| `--npz` | なし | 計算結果を保存するNPZのパス |
| `--max-range` | `4.24` | 表示する最大距離 [km]。デフォルトは短パルスの範囲 |
| `--clutter-bins` | `2` | 静止物の反射として除外するゼロ速度付近のビン数（片側）。1 ビンは約 0.19 m/s |
| `--snr-min` | `-3` | 平均ドップラー速度を表示する信号対雑音比の下限 [dB] |
| `--no-mark-short-files` | （破線を引く） | サイズが通常の半分程度のファイルの位置に引く破線を表示しない |

#### 処理内容

1. `_0000.bin` と、1 方位分（200 ヒット）に満たないファイルを除外する
2. 各ファイルの全スウィープを読み込み、200 ヒットごとに FFT したドップラースペクトルを全方位で平均する
3. ゼロ速度付近のビンを除いた電力を合計する
4. 速度ビン方向の中央値を雑音レベルとして差し引き、スペクトルの重心を平均ドップラー速度とする
5. ファイルの更新時刻を横軸にして並べる
   - 後から上書きされたファイルは更新時刻が取得時刻と大きく異なるため、前後 10 ファイルの中央値から 120 秒以上ずれた時刻を前後のファイルの時刻から補間する

#### 図を読むときの注意

- 縦軸は距離です。ビームの傾きは最大 5° なので、距離はレーダーからの高度とほぼ等しくなります（差は 0.4% 以下）
  - 海抜高度と比べる場合は、設置点の標高を足してください
- 破線は、記録が途中で途切れたファイル（サイズが通常の半分程度）の位置です
  - IQdata_20261030 では約 16 分ごとに出現し、破線の前後でエコーと雑音レベルが不連続になっていました。原因は確認中です
- 高度 0.18 km 未満は、送信直後の漏れ込みなどで常に強い値になるため、降水の判断に使わないでください

#### NPZファイルの内容（`--npz` 指定時）

| キー | shape | 説明 |
|---|---|---|
| `time` | `(ファイル数,)` | 各ファイルの時刻（UNIX 時間 [s]、補間済み） |
| `range` | `(2048,)` | 距離 [km] |
| `file_name` | `(ファイル数,)` | 入力ファイル名 |
| `short_file` | `(ファイル数,)` | 図に破線を引いたファイルを `True` とする配列 |
| `total` | `(ファイル数, 2048)` | 全速度ビンの平均電力 [dBm] |
| `moving` | `(ファイル数, 2048)` | ゼロ速度付近を除いた電力 [dBm] |
| `mean_velocity` | `(ファイル数, 2048)` | 平均ドップラー速度 [m/s]。信号が弱いゲートは NaN |
| `snr` | `(ファイル数, 2048)` | 信号対雑音比 [dB] |

### 5. 解析結果をブラウザで表示する（`webapp/`）

Web サーバーを起動している間、IQ データのフォルダの解析結果をブラウザで表示します。記録中のフォルダも表示でき、取り込みが完了したファイルを順に処理して図に追加します。

```bash
uv run webapp/server.py --root <IQデータのフォルダを含む親フォルダ>
```

起動するとブラウザで `http://127.0.0.1:8000/` が開きます。画面上部のプルダウンで、親フォルダの直下にある IQ データのフォルダを選びます。サーバーは起動した PC からのアクセスだけを受け付けます。

画面には次の図を表示します。

- 時間・高度図: 受信電力と平均ドップラー速度。内容は `plot_time_height.py` の図と同じ
  - 自動更新を有効にしている間は、5 秒ごとに新しく処理したファイルを追加する
  - 横軸は、推定観測時刻とファイルの更新時刻を画面で切り替えられる。初期値は推定観測時刻
  - 欠測の時間帯を斜線で示す。ファイルの間隔が通常の 3 倍（20 秒未満になる場合は 20 秒）を超えた時間帯を欠測とする
- 選択したファイルの図: 時間・高度図をクリックした時刻のファイルについて、次の 3 つを表示する
  - 高度プロファイル: 受信電力、平均ドップラー速度、信号対雑音比の距離分布
  - ドップラースペクトル: 全方位で平均したスペクトルの距離分布
  - PPI 電力マップ: 方位（鉛直からの傾き）ごとの受信電力

#### 推定観測時刻と欠測

記録ソフトは、データの書き込み（約 2.1 MB/s）が取り込み（約 3.1 MB/s）に追いつきません。書き込まれていないデータは約 1 GB のバッファに溜まり、ファイルの更新時刻は観測時刻より少しずつ遅れていきます。約 17 分でバッファが一杯になると、書きかけのファイルが途中で切れ、溜まっていた約 5 分の観測データが失われます。その後は最新の観測から記録が再開されます。

推定観測時刻は、この遅れを次の式で補正した時刻です。

```
推定観測時刻 = t − 0.30 × (t − t_s)
```

- t: ファイルの更新時刻
- t_s: 区間の先頭のファイルの更新時刻。区間は、記録が途中で途切れたファイル（通常の 75% 未満のサイズ）と、記録の最初のファイルで区切る
- 0.30: 2026-11-03 の追加観測で測った書き込みと取り込みの速さから求めた値（1 − 書き込みの速さ / 取り込みの速さ）

推定観測時刻の軸では、途切れの位置で失われた約 5 分が欠測として表れます。更新時刻の軸では、失われた時間は空白にならないため、途切れたファイルの位置に破線を引きます。

#### 取り込み完了の判定

取り込み中のファイルを読まないように、次のどちらかを満たしたファイルだけを処理します。

- 同じ記録の後続のファイルがあり、2 秒間隔の走査で前回からサイズと更新時刻が変わっていない
- 最終更新から `--settle` 秒以上経っている
  - 記録を終えた後の最後のファイルは、この条件で処理する

処理済みのファイルでも、サイズか更新時刻が変わった場合は処理し直します。処理結果は `webapp/cache/` に保存するため、サーバーを再起動しても処理し直す必要はありません。

| オプション | デフォルト | 説明 |
|---|---|---|
| `--root` | カレントディレクトリ | IQ データのフォルダを探す親フォルダ |
| `--port` | `8000` | 待ち受けるポート番号 |
| `--clutter-bins` | `2` | `plot_time_height.py` の同名のオプションと同じ |
| `--snr-min` | `-3` | `plot_time_height.py` の同名のオプションと同じ |
| `--settle` | `60` | 後続のファイルがない場合に、最終更新から何秒経てば取り込み完了とみなすか [秒] |
| `--cache-dir` | `webapp/cache` | 処理結果のキャッシュを保存するフォルダ |
| `--no-browser` | オフ | 起動時にブラウザを開かない |

## IQデータファイルについて

### ファイル命名規則

IQDatCapture によって以下の形式でファイルが生成されます。

```
<prefix>_yyyymmddHHMMSS_NNNN.bin
```

| 部分 | 説明 |
|---|---|
| `<prefix>` | ユーザーが指定したファイル名 |
| `yyyymmddHHMMSS` | 保存開始時のPC時刻 |
| `NNNN` | ファイル番号（0始まり、最大ファイル数 − 1 まで連番） |

> **注意**: 1ファイル目（`_0000.bin`）は設定した駆動範囲のデータが揃っていない場合があります。解析には **2ファイル目（`_0001.bin`）以降** を使用してください。

### バイナリフォーマット

IQデータはパルス圧縮後の生IQ信号を対数化・量子化したバイナリファイルです。

**ブロック構造**

1ブロックのサイズは 1040 Byte で、ヘッダー部とデータ部から構成されます。
方位ごとに 8 ブロック（I/Q × 分割番号 0〜3）で 1 スウィープを構成します。

```
1スウィープ (8ブロック)
├── I信号 分割番号0  [header 16B + data 1024B]
├── Q信号 分割番号0  [header 16B + data 1024B]
├── I信号 分割番号1  [header 16B + data 1024B]
├── Q信号 分割番号1  [header 16B + data 1024B]
├── ...
└── Q信号 分割番号3  [header 16B + data 1024B]
```

**ヘッダー部（16 Byte、リトルエンディアン）**

| フィールド | サイズ | 内容 |
|---|---|---|
| パラメータ番号 | 4 Byte | 未使用 |
| IQフラグ | 2 Byte | `0` = I信号、`1` = Q信号 |
| 方位角 | 2 Byte | 値 × 0.25 = 方位角 [deg]。鉛直観測では鉛直からの傾き（355°〜5° = −5°〜+5°） |
| 分割番号 | 4 Byte | 0〜3（レンジ方向を512ゲートずつ4分割） |
| スウィープ番号 | 4 Byte | 0〜35999 の連番 |

**データ部（1024 Byte）**

512 サンプル × 2 Byte（符号付き16bit整数、リトルエンディアン）。
パルス圧縮後のIQ信号は対数化（底2）された固定小数点形式で記録されています。

値 `d` からパルス圧縮後の振幅を復元する手順：

```
x = d / 2^9          # 固定小数点への変換（上位6bit: 整数部、下位9bit: 小数部）
X = 2^|x|            # 真数化
振幅 = sign(x) × X   # 符号付与
```

復元後の振幅からアンテナ入力端の電力を求める式：

```
P [dBm] = 20 * log10(sqrt(i^2 + q^2)) - offset
```

**オフセット値（キャリブレーション係数）**

| パルス種別 | レンジ範囲 | offset [dB] |
|---|---|---|
| 短パルス | 1〜213 bin（0〜4.24 km） | 387.7 |
| 長パルス | 214〜2048 bin（4.26〜40.94 km） | 398.1 |

> 簡易取扱説明書（E84AEA9100）の表 4 では、短パルス・長パルスとも 395.8 となっていますが、上の表の値が正しい値です。
